# DiskThinner 0.2.0

新增写入监控的诊断模式：除了看到哪里在变大，还能看到是哪个程序写的。只在本机运行，不联网。

## 下载哪个

| 文件 | 说明 |
|---|---|
| `DiskThinner-0.2.0-win-x64.zip`（约 2.8 MB） | 需要先装 [.NET 10 桌面运行库（x64）](https://dotnet.microsoft.com/download/dotnet/10.0)。没装时双击会提示去下载 |
| `DiskThinner-0.2.0-win-x64-selfcontained.zip`（约 46 MB） | 单个 exe，不需要装运行库 |

解压到任意目录，运行 `DiskThinner.exe`。支持 Windows 10 / 11 64 位。从 0.1.0 升级：直接用新目录替换旧目录，`%LOCALAPPDATA%\DiskThinner` 下的设置、快照和操作记录照常可用。

## 新功能：写入监控（诊断模式）

- 工具栏右侧的"写入监控"或增长分析页的"开启诊断"：选时长（1 / 4 / 8 / 24 小时）和模式，开始记录哪个程序在本机磁盘上新建、删除、重命名了文件。精确模式（默认）还记录写了多少，能估算每个程序让目录涨了多少。
- 需要管理员权限：普通权限下对话框的按钮是"以管理员身份重启并开始"。监控期间保持 DiskThinner 打开（可以最小化）；到时间、点"停止"或关闭窗口都会停止。
- 结果显示在这几个地方：
  - 增长分析："写入监控覆盖"卡片、覆盖时段的时间轴、每个目录的"写入进程"（例如 `uv.exe ← pwsh.exe ← Code.exe`）、写入进程排行；
  - 概览："增长最快"的"写入者"一列；
  - 空间浏览：详情里的"ETW"证据。
- 开销：本机实测，精确模式空闲时监控本身的 CPU 约 0.07%，内存增加约 22 MB，没有丢事件。编译这样的负载下也测不出变慢。
- 隐私：只在本机，按"目录 × 进程 × 小时"汇总，存在 `%LOCALAPPDATA%\DiskThinner\monitor.db`（默认保留 90 天，不超过 64 MB）。不记录文件名、文件内容和命令行，不打开被写入的文件。
- 为了在程序被强制结束时也能停下来，开始监控时会临时添加一个计划任务 `\DiskThinner\StopDiagnostic`。监控正常结束时删除，过期后也会自己删除。
- 设置里可以把写入监控改成"关闭"（不再提示开启），也可以改默认模式、默认时长和保留天数。
- 诊断用的无界面子命令：`DiskThinner.exe monitor --seconds N [--mode light|precise] [--report r.txt]`、`--cleanup`、`--status`，用法见 README。

## 其他改动

- 增长分析和概览的列表里，"文字 + 标签"同一格显示（例如进程链后面跟"实测"）。
- 主程序的 `--report` 增加写入监控和启动时间的几行（自动化验证用）。

## 已知问题

- 写入监控只在 DiskThinner 窗口开着、以管理员身份运行时记录，最长 24 小时；开机常驻的监控服务在后续版本提供。
- 这几种写入看不到写入者：
  - 监控开始前就打开的文件（数据库、虚拟磁盘、日志），写入对不上目录，只计入写入进程排行；
  - 虚拟磁盘，看不到里面是谁写的；
  - 缓存回写，记为"系统"。
- 轻量模式没有写入量。估算增长只算监控期间新建的文件，所以和快照的变化量不一定相等。
- 冷启动到窗口显示约 1.3 到 1.8 秒，没有达到 1 秒的目标（0.1.0 也超过）。
- 发布前在全新的 Windows Server 2022 和 2025（GitHub Actions）上做过冒烟测试，两个包的扫描、快照、写入监控（15 秒精确模式，核对解析器）都正常。还没有在干净的 Windows 10 / 11 桌面版上走过一遍。
- 没有代码签名，下载后 Windows SmartScreen 可能提示"未知发布者"。

完整的已知问题见仓库里的 `docs/known-issues.md`，阶段 2a 的验收结果见 `docs/phase2a-report.md`。
