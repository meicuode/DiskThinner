## 归属怎么定

优先级：规则写明了应用 → 系统位置和用户文件规则（"Windows""你自己的文件"）→ 推断 → 通用规则的兜底文字（"多个程序"，项目依赖显示"你的项目"）。规则决定类别和风险，推断只补"是谁的"，不改变能不能删。

推断只在"应用目录"位置做：`%LOCALAPPDATA%`、`%APPDATA%`、`%LOCALLOW%`、ProgramData、Program Files 下的一、二级目录，`Programs` 和 `Packages` 下的目录，`WindowsApps` 下的包目录，用户目录下的点目录（`.ollama` 等）。依据按顺序试：

1. 商店应用：包族名对上已注册的包。
2. 安装位置：已装软件的安装位置、正在运行的程序在这个目录里。装在"规则写明了应用"的位置里的程序不算（`%APPDATA%\uv\python` 里运行的 python.exe 不能让整个 uv 目录归 Python）。
3. 目录名：和软件名一致、是软件名开头的几个词、或等于主程序名（`%APPDATA%\Code` 对应 Code.exe）。一级目录名是某个厂商、这个厂商装了好几个软件时只说到厂商（"Google（多个应用）"），二级目录再细分（`Google\Chrome` → Google Chrome）。
4. 目录名和内置规则里的应用同名（`%LOCALAPPDATA%\uv`、`~\.gradle`）。
5. 目录里最大的几个程序文件的产品名一致（或公司一致）。认出来的程序要占这几个程序的八成以上。
6. 都对不上的 4 MB 以上 exe 单独读自己的版本信息（`~\.local\bin\claude.exe` → Claude Code）。

界面上来源标签只画在归属确定的那一级（"规则"实线框、"推断"虚线框），子项用浅色；详情里列出证据（已装软件、命令行工具、运行中、程序、目录名、商店应用），带程序路径的证据会在后台补一行数字签名。知道归谁但没有规则说明是什么的目录，类别列标"未识别"。

## 内存

M2 上半在 150% 缩放、加载规则后是 343 MB。这次先按 M1 的条件重测：100% 缩放、不加载规则，扫描本身就到了 329 MB。做了第一批改动（前两行）后，同样的命令几次结果在 254 MB 和 300 MB 之间跳；逐步记录工作集后发现跳动来自后台 GC，再做后两行：

| 改动 | 效果 |
|---|---|
| MFT 解析时，同一条记录已经有长文件名时不保存 8.3 短名 | 名称池容量从 4,089 万字符降到 3,460 万字符（少约 13 MB）；解析时记下的名字现在是 105 万条，按名称池的差额估算原来多出约 60 万条短名 |
| 名字条目紧排成 14 字节；条目数组按 1.5 倍扩容；父目录记录号暂存在节点的 Tag 里，省掉一个按节点数分配的数组；规则匹配结果去掉冗余的"节点 → 规则"数组，保护名单项改成 short | 每项几 MB |
| 扫描和匹配期间把 GC 切到 Batch 模式（不做后台回收），结束后恢复 | 后台回收进行时分配还在继续，峰值忽高忽低；改后各次结果一致 |
| 规则库和已装软件改到扫描结束、回收临时数组之后再加载；匹配和推断结束后再回收一次，然后才绑定界面 | 扫描峰值和匹配阶段不再叠加 |

改完后各步的工作集（100% 缩放，MFT）：扫描前 55 MB，读完 MFT 191 MB，建树后 254 MB（峰值），整理后 221 MB；回收后加载规则 204 MB，匹配完 240 MB，推断和汇总完 254 MB，回收后 233 MB，绑定界面后 238 MB。峰值出现在建树这一步，加载规则和推断不再抬高峰值。150% 缩放时界面绘制和截图位图多出 20–40 MB。进程的提交内存峰值约 221 MB。

## 界面

截图检查了 150% 缩放（MFT）和遍历扫描用户目录两种情况：概览、按目录（选中 `Program Files`、`Google\Chrome`）、按归属汇总、按类别汇总（`artifacts/m2b/final/`、`artifacts/m2b/dev/`）。

- 空间浏览顶部加了"按目录 / 按归属汇总 / 按类别汇总"切换（原型 .seg）。汇总视图第一层是组，展开是组里的各个位置；最大的一组默认展开。选中位置时方块图和详情联动，选中组时详情显示总量、可释放、最大的几个位置（可点击）和归属依据；双击位置或按回车回到按目录视图并定位。"只看可清理""只看未识别"在汇总视图里同样有效。
- 归属列和详情显示推断出的归属和来源标签；概览的"占用最多"也用同样的归属。
- 截图改用 PrintWindow：窗口被别的程序挡住时也能截到自己。默认窗口在 150% 缩放下列表出现横向滚动条的问题，通过收窄几列修正。

## 未完成和问题

- 商店应用的显示名大多是资源引用（`ms-resource:AppStoreName`），用 SHLoadIndirectString 只能解析一小部分，其余用包名拆词显示（"Windows Terminal""ASUSPC Assistant"）。
- 推断是启发式的，个别结果不准：`Program Files (x86)\Microsoft SDKs` 按程序的公司名归到"Microsoft（多个应用）"；`ms-playwright-go` 因为里面最大的程序是 node.exe 被归到 Node.js；Perplexity 的程序目录按版本信息显示成"Comet（The Comet Authors）"，没和规则里的"Perplexity Comet"合并。界面上都标了"推断"并列出依据。
- 已装软件只看当前用户（HKCU、当前用户的商店应用和 npm）；扫描整个盘时，其他用户目录里的推断只能靠 HKLM、目录名和程序版本信息。
- 运行中进程只取了映像路径，命令行和父进程留到 ETW（阶段 2）一起做。
- 42 条规则在这台机器上没有命中，仍需要在装了对应工具的机器上实测。
