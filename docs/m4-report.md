## 清理计划

新项目 `src/DiskThinner.Cleanup`，不引用 WinForms，按 Native AOT 要求编写。

每个"可执行"规则（有删除或白名单命令动作、不是兜底规则）命中的位置是一项，可清理部分不到 1 MB 的不列。按扫描时的风险分组，每组的默认处理方式和原型一致：

| 分组 | 默认 | 说明 |
|---|---|---|
| 安全 | 直接删除，勾选 | 缓存、临时文件、崩溃转储 |
| 需重新下载 | 有官方命令就运行命令，否则直接删除，勾选 | 用户目录里到处匹配的项目依赖（node_modules、虚拟环境）默认不勾选 |
| 无法恢复 | 直接删除，勾选；确认框里列出明细 | 会话记录、本地历史等 |
| AI 建议 | 默认不勾选 | 阶段 3 才有内容 |
| 已拦截 | 不能勾选 | 见下 |

"已拦截"里列出：规则说可以删但被保护名单拦下的位置；可清理位置里面受保护的文件（例如缓存目录里的 Login Data，执行时跳过）；1 GB 以上、只能在系统设置里处理的位置（分页文件、组件存储，点"查看步骤"看规则里的说明）；其他用户的目录；提权账户和登录用户不一致时的全部用户目录。

预计释放按处理方式在扫描树上模拟一遍，口径和执行器一致：不含硬链接共享和受保护的文件；`older_than_days` 按文件的修改时间；`keep_latest` 按直接子项保留最新的几个（目录按子树里最新的文件算）。官方命令按整个位置估计。普通权限的遍历扫描识别不了硬链接，计划页顶部会提示实际释放可能更少。

每一项都可以改成"手动清理（打开所在位置）"：执行时跳过，工具不删除任何东西；用户处理完点"重新测量"，只扫描这个位置，操作记录里写一条"手动清理"和实际释放量。

## 执行器

执行前逐项复核（研发方案 3.6 节），任何一条不通过都不执行，记一条"拦截"：

1. 从盘的根目录往下逐级看属性，任何一级是重解析点（junction、符号链接、挂载点、云文件占位符）都不执行。
2. 再查一次保护名单。
3. 规则仍然命中这个位置：路径模式按字符串匹配，`has_any`、`sibling_any`、`not_under` 条件按磁盘上现在的内容判断。
4. 另外：盘的根目录、用户目录的根、每个用户的目录本身、Windows、ProgramData、Program Files 永远不清理；处理方式必须是计划给出的那几种之一，删除方式必须是规则里的那一条，命令必须是白名单里的同一个对象；账户不一致时不碰用户目录、不运行命令。

删除：

- 自底向上，路径加 `\\?\` 前缀。
- 每个文件和目录都先打开句柄（不跟随重解析点），用句柄确认类型没变，再按句柄删除（`FileDispositionInfoEx`，POSIX 语义并忽略只读属性；文件系统不支持时清掉只读属性再普通删除）。确认和删除之间不会被换成别的东西。
- 正在处理的目录用不允许删除共享的句柄占住，处理期间不能被改名或替换。
- junction 和符号链接只删链接本身；其他重解析点（云文件占位符、去重文件等）不碰。
- 每一级都用"这个位置下面可能命中的保护项"再查一次，受保护的路径整个跳过。
- 有时间条件时，最近改动过的空目录也保留（可能是正在运行的程序刚建的工作目录）。
- 被占用的文件跳过，用 Restart Manager 查出占用的程序写进记录。确认框里勾选"有文件被占用时问我"后，会逐项询问；用户同意才调用 `RmShutdown` 请程序正常关闭（不带强制标志），然后再试一次。
- 每个文件的占用从句柄读取；链接数大于 1 的计入"共享"，不算释放。每一项的实际释放是执行前后 `GetDiskFreeSpaceEx` 之差。

官方命令：只运行 `KnownCommands` 白名单里的那一条；程序必须是已装软件探测到的（命令行工具目录、正在运行的程序，`.cmd` 在同一批目录里找），文件名必须和命令对得上；参数是固定数组，不拼命令行，`.cmd` 由系统交给 cmd.exe（参数都是常量）；标准输入直接关闭，命令要确认时不会卡住；10 分钟超时，超时结束整个进程树；输出截取 16 KB 写进操作记录。

账户一致性：启动时比较进程账户和登录会话的账户（`WTSQuerySessionInformation`）。不一致时计划顶部说明原因，用户目录全部列为已拦截，执行器也会再拒绝一次。

操作记录打不开时不执行清理（没有记录就不删）。删除不经过回收站，计划页底部和确认框里都写明了。

## 操作记录

`%LOCALAPPDATA%\DiskThinner\user.db` 的 `audit_log` 表：时间、同一次清理的编号、操作（删除 / 运行命令 / 手动清理 / 拦截）、对象、名称、计划时的大小、实际释放、依据（规则编号、保护名单原因、执行前复核的原因、"用户确认了明细"）、结果、明细（删了多少、跳过多少、被谁占用、出错的前几条、命令输出）、文件数、错误数。触发器拒绝 UPDATE 和 DELETE。

操作记录页按原型：累计释放、最近一次、被拦截、AI 建议被采纳（阶段 3 之前是 0）四张卡片；全部 / 删除 / 运行命令 / 手动清理 / 拦截筛选；列表只读，双击看明细；导出 CSV（UTF-8 带 BOM；以 `= + - @` 开头的字段加单引号，防止表格软件当成公式）。

## 界面

截图检查了 150% 缩放：C 盘（MFT）的清理计划页和确认框，测试盘的操作记录页（`artifacts/m4/final/`）；普通权限扫描 `%LOCALAPPDATA%` 的清理计划页和确认框（`artifacts/m4/ui/`）。

- 清理计划页按原型：分组行（风险标签 + 默认方式 + 项数和大小）、复选框、项目、路径、大小、来源标签、处理方式下拉框、提示、"查看 / 打开位置 / 重新测量 / 查看步骤"；底部是已选、预计释放、"删除是永久的，不经过回收站"、导出清单和执行清理。双击或回车回到空间浏览定位。
- 确认框按原型：按处理方式汇总；"以下内容删除后无法恢复"列出每项的文件数和最早、最晚的修改时间，可以看明细；正在运行、规则要求先关闭的程序；默认焦点在"返回修改"，回车不会直接开始。
- 执行时显示进度（第几项、这一项删了多少），可以停止（当前文件处理完就停）；完成后汇总实际释放和预计释放，切到操作记录。
- 空间浏览的详情面板："运行 uv cache clean（推荐）"和"加入清理计划"可以点了，都只是在计划里选中这一项（作用在规则命中的位置上），确认之后才执行。
- 截图里发现的问题已修正：DataGridView 不会自动缩放列宽，改为按显示器 DPI 设置；确认框在 150% 缩放下被截断，改为加载后按实际 DPI 排版、内容多时可以滚动；"普通权限识别不了硬链接"从每一行的提示挪到计划顶部；ASP.NET 临时编译文件被当成"项目依赖"默认不勾选，改为只有在用户目录里到处匹配的构建产物规则（node_modules、虚拟环境）才默认不勾选。最后一项在管理员截图之后修正，有单元测试覆盖，没有重新截图。

## 未完成和问题

- 没有在真实的 C 盘上执行过清理，这一步留给用户自己决定。白名单里的官方命令（uv、npm、dotnet 等）也没有真正运行过，测试只覆盖了运行方式（白名单、程序名、输出、超时）。
- `RmShutdown`（请占用的程序关闭）没有自动化测试：测试里占用文件的是测试进程自己，关掉它测试就中断了。查出占用程序的部分有测试。
- 研发方案要求删除类测试只在测试盘上跑。这里普通测试在 `%TEMP%` 下新建的目录里跑，执行器另外用 `RequiredRoot` 限定只能删这个目录里面的东西，junction 和硬链接的目标也都在里面；在测试盘上跑的是同一套测试，并且核对卷标。
- C 盘的计划有 185 项，大多是各个 Chromium 内核程序的缓存，列表较长；以后可以按规则合并显示。
- 重新测量用遍历扫描，识别不了硬链接；文件按逻辑大小。
- 清理计划页用 DataGridView，读屏软件能读出单元格内容，但分组行是自绘的；可访问性还没有用"讲述人"实测。
