# 已知问题和限制（0.1.x / 0.2 开发中）

从各阶段报告里汇总，2026-10-29 更新。修好一项就从这里删掉，并在对应的报告或研发方案里记一笔。

## 扫描

- 普通权限下用遍历扫描：硬链接每个名字都算一次（C 盘约 12 万个附加名字，汇总可能超过已用空间）；压缩和稀疏文件按逻辑大小算，偏大；看不到备用数据流；分配大小按簇估算。以管理员身份运行改用 MFT 扫描就没有这些问题。
- 遍历扫描的峰值内存（M1 实测 359 MB）比 MFT 扫描高，超过 300 MB 的目标。
- 文件多的盘（CI 的虚拟机比开发机多 35% 到 70% 的文件）MFT 扫描后峰值内存超过 300 MB；慢盘上 MFT 扫描超过 10 秒（CI 虚拟机 15.6 秒）。
- 硬链接的大小只能算在一个目录里：`Windows\WinSxS` 和 `System32` 和 WizTree 比一边多一边少（各约 5%），总量一致。
- 目录上的备用数据流只计入统计里的 `AlternateStreamBytes`，不计入目录占用。`AlternateStreamBytes` 是逻辑大小，含 `$Bad:$Bad` 这类元数据流，不能当作占用看（界面没有显示它）。

## 规则和归属

- 42 条规则在开发机上没有命中（uv 之外的语言工具链、Docker / WSL、JetBrains 等），要在装了这些工具的机器上实测。
- 归属推断是启发式的，个别不准：`Program Files (x86)\Microsoft SDKs` 归到"Microsoft（多个应用）"，`ms-playwright-go` 归到 Node.js，Perplexity 的程序目录显示成"Comet（The Comet Authors）"。界面上都标了"推断"并列出依据。
- 商店应用的显示名大多解析不出来，用包名拆词显示。
- 已装软件只看当前用户；扫描整个盘时，其他用户目录里的推断只能靠 HKLM、目录名和程序版本信息。
- 规则库的说明文字没有放进 resx（是数据，阶段 4 和英文界面一起做）。

## 快照和增长

- 快照只记录到第 32 层，更深处的变化报在第 32 层的目录上。
- 快照只记文件数，分不出新建和删除。两个快照相隔很远、中间没有连续快照时，个别目录的变化量是近似值（误差不超过记录阈值）。

## 写入监控（阶段 2a）

- **使用条件**
  - 只在 DiskThinner 窗口开着、以管理员身份运行时监控，最长 24 小时。没有监控的时段只能看到哪里变了，看不到是谁写的。常驻服务是阶段 2b。
- **看不到写入者的情况**
  - 监控开始前已经打开的文件（数据库、虚拟磁盘、日志），写入对不上目录。2a.1 实测这类写入占空闲时写入量的 71%、编译时的 33%。它们只计入写入进程排行，主要目录写"对不上目录"。
  - 虚拟磁盘（vhdx）只能看到虚拟机进程在写，看不到虚拟机里面是谁写的。
  - 缓存回写和内核的写入记为"系统（缓存回写或内核）"，看不到真正写文件的进程。
- **口径和模式**
  - 轻量模式只记新建、删除、重命名，没有写入量；也看不到"关闭时删除"的临时文件的删除。
  - 估算增长只算监控期间新建的文件，按逻辑大小。监控开始前已有的文件变大只有写入量；只预分配不写的文件估算增长为 0。所以估算增长和快照的变化量不一定相等。
- **强制结束和兜底任务**
  - DiskThinner 被强制结束时，会话会留到下次以管理员身份打开（或运行 `monitor --cleanup`），或者到计划结束时间约 1 分钟后被兜底计划任务停掉。
  - 兜底任务注册失败时只记警告，不阻止监控。
- **只由单元测试覆盖、没有实机测过的**
  - 睡眠唤醒、改系统时间、用电池时的兜底任务、用另一个管理员账户提权、UAC 点"否"。
- **冷启动**
  - 冷启动到窗口显示（中位数）：0.1.0 是 1.35 秒，现在是 1.80 秒，都超过研发方案 1.3 节 1 秒的目标。单次之间抖动比差值大，阶段 2b 开始前在空闲的机器上复测（见 `docs/phase2a-report.md`）。

## 清理

- 没有在真实的 C 盘上执行过清理；白名单里的官方命令（uv、npm、dotnet 等）没有真正运行过，测试只覆盖了运行方式。
- C 盘的计划有 185 项，大多是各个 Chromium 内核程序的缓存，列表很长，还没有按规则合并显示。
- 手动清理后的"重新测量"用遍历扫描，识别不了硬链接，按逻辑大小算。
- "关闭并继续"：同意后，Restart Manager 像注销时一样询问程序。没有普通窗口的程序（托盘程序、后台程序）由进程里隐藏的窗口代答，通常直接退出，不会提示保存；询问框里"程序可能会提示保存"对这类程序不成立。

## 界面和可访问性

- 没有用"讲述人"实测过（见下面的清单），包括 2a 新加的写入监控胶囊、对话框、覆盖时段和写入进程排行。自动检查只保证控件有名字、颜色对比度够。
- 没有处理高对比度主题：界面用固定的配色自绘，开启高对比度后颜色不会跟着变。
- WinForms 会把前一个标签的文字当作没有名字的容器的名字，个别容器读出来不相干（例如设置页的"142 条 · 随程序更新"）。
- 清理计划页的分组行是自绘的，读屏软件读到的是单元格内容。
- 没有暗色模式和英文界面（阶段 4）。

## 发布和 CI

- 没有代码签名，下载后 SmartScreen 可能提示"未知发布者"。
- 没有在干净的 Windows 10 / 11 桌面版上验收（步骤见 `docs/m5-report.md`）；Windows Server 2022 / 2025 上的冒烟测试每次推送都跑。
- CI 在 `9aaef18` 和 `910be4d` 上测试步骤卡住，被 `--blame-hang-timeout` 结束（`910be4d` 那次没跑完的是 `GrowthUiTests.GrowthPageComparesSnapshotsWithTheCurrentScan`）。卡住只出现在测试里：xUnit 按测试类并行，同一个测试进程里几个 STA 线程同时创建、销毁窗口会互相卡住（本机加压并行跑时复现过一次，转储里一个线程拿着 WinForms 创建窗口的锁不动，其他线程在等它）。主程序只有一个界面线程，不受影响。所以界面测试（包括 `UiAutomationTests`）改为串行；单个界面测试 60 秒没结束就自己失败，并写出卡在哪一步。

## 讲述人人工检查清单

每个版本发布前在 100% 和 150% 缩放下各走一遍（Ctrl+Win+Enter 开关讲述人）：

1. 启动后按 Tab：依次读出磁盘选择、导航六项（"概览 单选按钮 已选中"），上下方向键在导航里移动，Enter 切换页面，进入页面时读出页面名。
2. 空间浏览：Tab 到文件树，上下方向键逐行读出名称、大小、占上级、最后写入、归属、类别 / 风险；右方向键展开，左方向键收起。
3. 方块图：Tab 到方块图，方向键移动时读出选中块的路径和大小，Enter 进入目录，Backspace 返回上一级；详情面板跟着变化。
4. 清理计划：逐项读出勾选状态、名称、大小、风险；空格切换勾选；"确认清理"对话框打开时读出要删除的总量和"删除是永久的"，Esc 取消。
5. 增长分析和概览：图表读出文字版本（AccessibleDescription），表格逐行可读；"写入进程"一格读成"进程链 实测"或"未监控"，覆盖时段读出各个时段。
5a. 写入监控：Tab 到工具栏的写入监控胶囊，读出"写入监控：关闭 · 开启诊断"（或"诊断中……剩余……· 停止"），Enter 打开对话框；对话框里读出时长、模式和注意事项，Esc 取消；停止前的确认框读出"停止写入监控？"。
6. 设置：每个下拉框和复选框读出对应的标签，保护目录列表可以用键盘添加和删除。
7. 开启高对比度（左 Alt + 左 Shift + Print Screen）：记录哪些文字、焦点框、选中状态看不清（目前预计会有，见上）。
8. 200% 缩放下文字不截断、不重叠。
